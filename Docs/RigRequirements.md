# Требования к ригу: FP-оружие и FP-руки (мобильный шутер)

Документ для художников и аниматоров. Цель: риг импортируется в Unity без ручных правок, укладывается в мобильный бюджет скиннинга и одинаково работает со всеми анимациями и IK.

## 1. Общие правила экспорта

| Параметр | Значение |
|---|---|
| Единицы | 1 unit = 1 m, scale на корне = 1 |
| Оси | Y-up, вперёд +Z (в Blender: Forward −Y, Up Z, «Apply Transform»), в Maya: Y-up по умолчанию |
| Трансформы | Freeze/Apply на мешах и костях до скиннинга, без отрицательного scale |
| Формат | FBX 2020, только deform-кости (контроллеры не экспортируются) |
| Анимации | Отдельные FBX на клип, `A_<Объект>_<Действие>`, 30 fps, без Euler-флипов |
| Root motion | Не используется: корень неподвижен |

## 2. Именование

- Меши: `SK_` для скиннинговых и `SM_` для статики. LOD-ы через суффиксы `_LOD0`, `_LOD1`, `_LOD2`.
- Кости: `b_` + часть + сторона суффиксом: `b_hand_l`, `b_index_02_r`.
- Кости оружия: `b_weapon_root`, `b_slide`, `b_magazine`, `b_trigger`, `b_bolt`, `b_charging_handle`.
- Сокеты (кости без весов, используются только как точки привязки): `socket_muzzle`, `socket_shell_eject`, `socket_lhand_ik`, `socket_sight`, `socket_magazine_drop`.

## 3. Бюджеты скиннинга

| Объект | Кости, макс. | Весов на вершину | Треугольники LOD0 |
|---|---|---|---|
| FP-оружие | 20 | 2 (механика жёсткая, обычно 1) | 12 000 |
| FP-руки | 45 | 4 | 8 000 |
| Персонаж 3P (справочно) | 60 | 4, на дальних LOD 2 | 15 000 |

Почему так: каждая кость и вес на вершину увеличивают стоимость скиннинга на GPU/CPU. На слабых Mali/Adreno FP-слой рендерится каждый кадр крупным планом, поэтому экономить надо именно на нём.

## 4. Иерархия FP-рук

```
b_root
└── b_camera            (сюда цепляется камера, анимация камеры = отдача и покачивание)
    └── b_spine_fp
        ├── b_clavicle_l → b_upperarm_l → b_forearm_l → b_hand_l → пальцы
        │                  b_forearm_twist_l (скинится, отдельный поворот предплечья)
        ├── b_clavicle_r → ... → b_hand_r
        └── b_weapon_attach (оружие вешается сюда, рука R ведёт оружие)
```

- Пальцы: 3 фаланги, большой палец 3 кости. Мизинец и безымянный можно объединить для LOD.
- Twist-кости: по одной на предплечье, чтобы не было «конфетной обёртки» при повороте кисти.

## 5. IK/FK

- Правая рука ведёт оружие в FK (анимация), левая рука в **two-bone IK** к `socket_lhand_ik` на оружии. Одна анимация рук подходит к разным стволам, если у них разные цевья.
- Pole target локтя в риге называется `ik_pole_elbow_l` и смотрит вниз и наружу.
- В Unity: Animation Rigging → `TwoBoneIKConstraint` (root = `b_upperarm_l`, mid = `b_forearm_l`, tip = `b_hand_l`), вес IK кривой в клипе: 0 на перезарядке (рука уходит к магазину), 1 в остальное время.
- В исходнике (Maya/Blender) должно быть переключение IK/FK для аниматора. В FBX уходит только запечённый результат на deform-кости.

## 6. Blend shapes

- Только там, где кости не справляются: обжатие перчатки на рукояти, деформация ремня или чехла.
- Не больше 4 шейпов на меш FP-слоя. Нормали в шейпах не сохранять, если разница не видна (`Blend Shape Normals: None`): это экономит память и время импорта.
- Имена шейпов: `bs_<описание>`, например `bs_grip_squeeze`.

## 7. Чек-лист ревью рига

- [ ] Scale корня = 1, единицы в метрах, ориентация совпадает с эталонной сценой.
- [ ] Число костей и весов на вершину в бюджете (проверяет `Tools/Portfolio/Asset Validator`).
- [ ] Нет весов на сокетах и служебных костях.
- [ ] Нормализованные веса, нет вершин без весов.
- [ ] Twist-кости работают, при повороте кисти на ±90° нет схлопывания.
- [ ] Bind pose совпадает с первым кадром idle (иначе на импорте будет рывок).
- [ ] Левая рука в IK стоит на `socket_lhand_ik` без зазора на всех стволах.
- [ ] Сокеты `socket_muzzle` и `socket_shell_eject` смотрят по +Z (ось выхода VFX).
- [ ] Анимации без ключей на scale и без лишних каналов (компрессия клипов `Optimal`).
